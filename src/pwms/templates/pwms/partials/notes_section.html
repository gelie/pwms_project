{% comment %} The note log on a workflow detail page: the notes recorded against the record, the form that adds one, and inline editing of a note. Notes are rows (``pwms.WorkflowNote``), so each one carries its own author and timestamp. Where a type also has a ``notes`` column — the BRS attribute (BR02.3.13) edited with the record — its text is shown above the log rather than being folded into it. A note is its author's to edit or delete, and only while they may still edit the record, so the per-note controls appear only where ``row.can_change`` is set. Rendered standalone as the HTMX response to an add, an edit or a delete, and included by ``pwms/workflow-detail.html`` for the first paint (every workflow detail page gets this panel through that block's default). The response root is ``#notes-section`` and callers swap it with ``outerHTML``; the status alert lives outside it (in the tab pane) so it survives that swap. Context (from ``pwms.views._notes_context``): note_rows, record_notes, can_edit_notes, notes_form, target_content_type, target_object_id; plus notes_status ({level, message}) when a note was just added, edited or deleted. {% endcomment %}
