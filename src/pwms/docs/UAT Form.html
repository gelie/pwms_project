2. How to complete this form

  1. Work through the scenarios in order. For each one, carry out the steps in What to do and compare what happens with Expected result.
  2. Record one result per scenario by circling a letter in the Result column. A scenario marked * is critical to acceptance and must pass for the section to accept the system.
  3. If the result is not P, write what actually happened in Evidence / defect ref, and add a row to the defect log (§14) giving it an ID. Put that defect ID in the evidence column so the two tie together.
  4. If an earlier defect stops you reaching a scenario, mark it B and name the defect that blocked it. Do not guess.
  5. Mark a scenario N only where it genuinely does not apply to the section's work — say why in the evidence column. Where a scenario depends on administrator configuration (for example email or SharePoint), note that in your comments rather than marking it as failed.
  6. Attach screenshots where they help. Name each one with the scenario ID (for example E2-blocked.png) and list the files in §16.
  • P — Pass: as expected
  • F — Fail: not as expected
  • B — Blocked: could not be carried out
  • N — Not applicable

Severity — use this to grade every defect you log

S1 — Blocking The section cannot carry out real work, or data is lost or corrupted.
S2 — Major A core task gives the wrong result and there is no acceptable workaround.
S3 — Minor The task works but with an awkward workaround, or a field, label or figure is wrong.
S4 — Cosmetic Appearance or wording only; nothing about the work changes.

13. Before you log a defect — expected behaviour

The following are deliberate and confirmed with the section. Please do not log them as defects; note them in your comments only if they cause a problem for the section's work.

1. A blocked move may look unblocked The Referrals tab's Conditions column can show a dash for the report's closing move even though it needs the ATC update. The confirmation page is the authority on whether a move may be taken.
2. An agreement's first stage is not reachable Submitted for tabling on an international agreement has no incoming move, so a record starts at Agreement Tabled – referred to Committee.
3. Lists are not paged Registers, alerts and the timeline show a fixed number of rows without page controls. Use search and the filters to narrow a long list.
4. The header search box is decorative The search box in the page header does not search anything. Use the Search on the page you are working in.
5. The report type does not change an export Choosing Referrals or Activity changes what is previewed on screen, but a workbook, PDF or web-page export always carries the summary, breakdowns, register, activity and referrals. The CSV is the register only.
6. A share is fixed once created A share link's recipients, expiry and message cannot be changed afterwards, and only an administrator can revoke it. It also stops working if the account that created it is removed.
7. Email needs configuration Alert and shared-report email depends on the mail service and the background worker being configured and running. If email does not arrive, the in-app bell is still accurate — raise it with the administrator.
8. Detaching keeps the file Detaching removes the link from the record only; the file stays in SharePoint. Re-uploading the same file name into the same folder becomes a new version.
9. Document links expire A SharePoint address resolved by PWMS is short-lived. Send the record, not the resolved address.
10. Reference numbers restart each January A delegation report's and an agreement's reference begin again at 0001 each year, so the full reference including the year should always be quoted.
11. Changing the stage on the edit form The edit form can move a record's stage without taking a transition. It is an administrator's correction tool: it checks no requirement and records no move. If you used it while testing, say so — it is not a defect.
