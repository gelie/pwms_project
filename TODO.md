I have a clear picture now. The project is unusually mature in its domain core (workflow engine, RBAC, audit, docs), so the gaps are mostly engineering and operational, plus a few explicitly unfinished domain 
 features. Here's my assessment, grouped by what would actually move the needle.                                                                                                                                  
                                                                                                                                                                                                                  
 1. Engineering infrastructure — the biggest gap                                                                                                                                                                  
                                                                                                                                                                                                                  
 The single largest risk is that none of the correctness guarantees are protected by automation.                                                                                                                  
                                                                                                                                                                                                                  
 - No CI at all — no .github/workflows, no GitLab CI, no pre-commit, no Makefile. There are ~10 test modules and 47 migrations, but nothing runs them on a commit. A parliamentary system with audit guarantees   
   should not rely on someone remembering to run tests.                                                                                                                                                           
 - No coverage measurement — pytest-cov/coverage isn't configured. You can't tell whether the RBAC and transition guards (the security-critical parts) are actually covered.                                      
 - No pre-commit hooks — ruff is configured and installable but nothing runs it. It currently reports 104 lint errors (31 blind except, 29 bare/vanilla raises, 23 unsorted imports). These are the kind of       
   silent except Exception that can swallow RBAC failures.                                                                                                                                                        
 - No lockfile verification / dependency audit — requirements.txt is 63 KB and uv.lock exists, but nothing checks for known CVEs (pip-audit) or that the lock is in sync.                                         
                                                                                                                                                                                                                  
 Highest-value single action: a CI workflow running ruff check, makemigrations --check --dry-run, and the test suite. The --check --dry-run matters especially — with 47 hand-written migrations there's real     
 risk models and migrations have drifted.                                                                                                                                                                         
                                                                                                                                                                                                                  
 2. Production / security hardening                                                                                                                                                                               
                                                                                                                                                                                                                  
 - ALLOWED_HOSTS is hard-coded to dev hosts (workflows-dev.parliament.gov.za, 172.16.0.114) in settings.py, not environment-driven. DEBUG/SECRET_KEY are correctly env-driven, so this is the odd one out and     
   will bite on deployment.                                                                                                                                                                                       
 - No security headers configured — no SECURE_SSL_REDIRECT, SECURE_HSTS_SECONDS, SESSION_COOKIE_SECURE, CSRF_COOKIE_SECURE, SECURE_CONTENT_TYPE_NOSNIFF. For a system holding encrypted MP ID numbers, this is a  
   real gap.                                                                                                                                                                                                      
 - No CSP — the app is HTMX/Bootstrap-heavy; a django-csp policy would meaningfully reduce XSS blast radius.                                                                                                      
 - No DRF throttling — REST_FRAMEWORK sets auth and IsAuthenticated but no DEFAULT_THROTTLE_CLASSES. The audit API is unthrottled.                                                                                
 - BasicAuthentication enabled on the API — combined with no throttle, that's credential-stuffing exposure. Consider session/token only.                                                                          
 - No secret-scanning — .env is correctly git-ignored, but there's no gitleaks/detect-secrets safety net given how many secrets (LDAP bind password, Oracle creds, Graph client secret, two crypto keys) live     
   there.                                                                                                                                                                                                         
                                                                                                                                                                                                                  
 3. Unresolved architectural decision — the django-ninja spike                                                                                                                                                    
                                                                                                                                                                                                                  
 src/pwms/api/ninja.py (103 lines) mirrors the DRF audit endpoints, is mounted at /ninja/, and its own docstring says "Remove this module… if you keep DRF." It's shipped spike code sitting in production URLs.  
 The roadmap flags this too ("reconcile/remove the django-ninja spike once the API decision is made"). Decide and delete — carrying two API stacks into maintenance is a needless tax.                            
                                                                                                                                                                                                                  
 4. Explicitly unfinished domain features (from the roadmap + code)                                                                                                                                               
                                                                                                                                                                                                                  
 - SharePoint version restore — version list/download work, but restoring a superseded version needs a write-scoped Graph permission not held. Users can see history but can't roll back.                         
 - Version pinning — you can't pin "the version tabled" so it survives later revisions. For a legislative record, this is arguably important, not cosmetic.                                                       
 - HTML alert email templates — alert mail is plain-text only; report-share mail already does HTML+text. Low effort, visible polish.                                                                              
 - Markdown → HTML rendering for note fields — markdown is declared as a dependency but unused.                                                                                                                   
 - Calendar view — the legacy update_event_statuses calendar concept was dropped; if meetings/sessions are wanted it's a new model.                                                                               
 - Motions and Questions instruments — mentioned as "planned" but not started.                                                                                                                                    
 - Web UI gaps — Share / Comment / Manage actions are RBAC-gated but still admin- or API-only; create/edit forms lack the flatpickr date pickers; committee/House dashboards and a django-filter search layer are 
   declared-but-unbuilt; admin for managing workflow definitions lags.                                                                                                                                            
                                                                                                                                                                                                                  
 5. Reliability of background work                                                                                                                                                                                
                                                                                                                                                                                                                  
 - Delivery depends on django-background-tasks + manage.py process_tasks running. start_pwms.sh starts only gunicorn — it does not start the task worker or systemd timers. So the "queued email / scheduled      
   reports / deadline alerts" features silently do nothing unless the worker is separately supervised. There's no health check or alert on a stalled queue.                                                       
 - No dead-letter / retry visibility beyond the Notification.error column; failures are logged in the DB but nothing surfaces them operationally.                                                                 
                                                                                                                                                                                                                  
 6. Code health / maintainability                                                                                                                                                                                 
                                                                                                                                                                                                                  
 - God modules — views.py is 2,646 lines, models/workflows.py is 2,910 lines, forms.py 1,068. The workflow base class alone should probably split (transitions, RBAC, events, progress).                          
 - 47 migrations with lots of data backfills (e.g. 0044 backfilling referral access). No migration tests or reversibility checks; the roadmap notes the schema "can be dropped and recreated safely in            
   development," which suggests rollback isn't exercised.                                                                                                                                                         
 - Test suite is targeted, not broad — heavy on reports/attachments/notifications, but the roadmap itself admits "broader test coverage and CI" remain. No performance/load tests.                                
                                                                                                                                                                                                                  
 7. Data & integration risks                                                                                                                                                                                      
                                                                                                                                                                                                                  
 - SharePoint site-member sync is silently skipped because the app token lacks Sites.Manage.All. Permission mapping PWMS-group→SharePoint-site is designed but not enforced in production; access in SharePoint   
   and access in PWMS can drift.                                                                                                                                                                                  
 - Oracle/legacy sync commands (sync_users_oracle, sync_groups_oracle, sync_roles_oracle) create placeholder users and have collision-fixing "not implemented yet" (validate_memberships.py). Identity            
   reconciliation is a known soft spot.                                                                                                                                                                           
                                                                                                                                                                                                                  
 ────────────────────────────────────────────────────────────────────────────────                                                                                                                                 
                                                                                                                                                                                                                  
 If I had to rank what actually improves the project                                                                                                                                                              
                                                                                                                                                                                                                  
 1. Add CI (ruff + makemigrations --check + tests) and coverage tracking — nothing else matters as much.                                                                                                          
 2. Harden settings — env-driven ALLOWED_HOSTS, secure cookies/HSTS/nosniff, CSP, DRF throttling.                                                                                                                 
 3. Supervise the task worker and alert on a stalled queue — otherwise whole shipped features are dead in production.                                                                                             
 4. Resolve and remove the ninja spike.                                                                                                                                                                           
 5. SharePoint version pinning/restore — the one domain feature with real legislative-accuracy value.                                                                                                             
 6. Split views.py / models/workflows.py and fix the 104 lint findings.                                                                                                                                           
                                                                                                                                                                                                                  
 The standout observation: this project's documentation and domain modelling are well ahead of its operational engineering. It's a thoughtfully designed system that isn't yet safeguarded like a production      
 system handling sensitive identity data.
